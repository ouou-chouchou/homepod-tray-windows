# HomePodTray v0.1.1 — Windows x64 Pre-release

这是 0.1.0 之后的修复版，解决在干净 Windows 系统上连接约 3 秒后自动断开的问题。

## 本版修复

**引擎主循环在默认系统定时器下跑不满实时速率。**

引擎线程依赖 `poll/WSAPoll` 的 2 ms 超时驱动主循环，但工程内没有调用 `timeBeginPeriod`。Windows 默认时钟节拍为 15.6 ms，实测 2 ms 套接字等待实际耗时 15.56 ms，主循环只有约 64 Hz；每次循环最多搬运 441 帧（10 ms 音频），即 28.2k 帧/秒，低于采集端的 44.1k 帧/秒。队列以约 15.9k 帧/秒累积，约 2.8 秒达到 44100 帧的守护阈值。

症状：

- 连接握手全部成功（RTSP / pair-verify / RECORD / stream SETUP 全通过），能听到约 3 秒声音且明显卡顿；
- 随后报「采集队列超过 1 秒：已停止，避免静默丢帧」并断开；
- 与采样率无关：48 kHz、44.1 kHz、重采样、直通分支，断开时间都是 3.0 秒。

修复方式：引擎线程启动时 `timeBeginPeriod(1)`、结束时 `timeEndPeriod(1)`，并把每次搬运上限由 441 帧放宽到 4410 帧（循环被拖慢时的第二层保险）。同进程实测 `select(2 ms)` 由 15.56 ms 降到 2.42 ms。

Windows 10 2004 起 `timeBeginPeriod` 只对调用进程生效，外部进程无法代为提升，因此修复必须落在程序自身。0.1.0 的验收环境恰好有其他提升定时器精度的程序（浏览器、游戏、灯效软件等），掩盖了该问题。

## 安装步骤

1. 解压完整 ZIP，运行 `01-HomePodTray-Setup.exe`，安装到当前用户目录。
2. 安装器可选请求管理员权限添加仅针对 HomePodTray、远端为 `LocalSubnet` 的入站 UDP 规则；拒绝授权仍可安装。
3. 打开包内 VB-Cable 官方链接，下载并完整解压驱动包，以管理员身份运行 x64 安装程序，然后重启电脑。
4. 在 Windows 音量混合器把需要投射的播放器输出设为 `CABLE Input`（**不要选 `CABLE In 16 Ch`**），其他应用保留原输出。
5. 确认电脑与已初始化的 HomePod 在同一局域网，打开 HomePodTray，选择 HomePod、虚拟声卡和投射应用。
6. 选择「仅 HomePod」，点击「应用设置」和「连接」，开始播放。

## 已知限制

本地与 HomePod 输出未对齐延迟；完整 PIN/密码配对、IPv6/跨网段发现、任意多物理输出、自动更新尚未实现。采集支持 44100/48000 Hz，最终输出固定 44100 Hz / 16-bit / 双声道，24 位音源会在末段量化到 16 位。日志可能含接收器地址，反馈问题前请检查敏感内容。
